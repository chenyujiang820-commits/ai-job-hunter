# 开发日志（2026-08-12 · Hermes 版）

## 修复记录

### R1: 诚实护栏子串误判漏洞（严重）
**发现方式**：验证集全量跑批后人工核查 boss-02 简历文本，发现 273.9 万（旧值）通过护栏。
**根因**：`hardCheck` 用字符串包含匹配（`sn.includes(n) || n.includes(sn)`），"273.9万".includes("7.9万") === true → 273.9 被误判为可回源。
**修复**：改为数值化比较（`parseToAbs`：解析数值+单位→绝对值，万→×10000），±1 容差处理约数（70余家≈70家）。
**回归测试**：新增 3 条防回归用例（273.9 必须拦 / 245.8 与 7.9 独立匹配 / 约数容差）。
**教训**：数字匹配必须数值化，字符串包含是错误抽象。

### R2: 推理模型空 content（T1 draft）
**现象**：长 prompt 时 completion tokens 全被 reasoning 吃掉，content 为空 → JSON 解析失败。
**修复**：draft 调用加 `reasoning_effort: 'none'`（生成任务不需要推理）+ maxTokens 3000。

### R3: 免费档 TPM 限流（429）
**现象**：大请求（6000 max_tokens + 全量事实清单）触发 FreeUsageLimitError。
**修复**：① 压缩事实清单（截断字段）② max_tokens 降到 3000 ③ 429 用指数退避（3s→6s→12s）④ 跑批脚本 LLM 调用间隔 15s。

### R4: LLM 编造汇总数字（"900万"）
**现象**：draft 自行相加多个项目金额得出"约900万"写入简历。
**修复**：system prompt 加硬约束"禁止自行汇总/推导新数字，只允许原样引用单一事实数字"。
**补充**：护栏 HARD 规则本应拦截（900 万不在 source），双重防线。

### R5: 源简历数据笔误（273.9 → 273.7）
**发现**：T2 终检抓到"数字计算错误"；人工核算 245.8+7.9+20=273.7。
**处理**：老板确认 → 修正 `data/source_resume.json`。

### R6: R4 修复后"900万"复发（长 JD 压力下）
**现象**：增强版 prompt 上线后跑 boss-02，draft 再次把 245.8+7.9+20 等相加写成"累计签约金额超900万"。
**修复**：draft prompt 新增 6b「数字清单制」——事实清单中每个金额/数量是独立事实，只能逐个原样引用，写完每行自查"数字能否逐字回源，找不到即编造"。
**验证**：boss-05 重跑 17 条 claim 全过、无 900 万；护栏 HARD 仍作为第二道防线（即使漏过也会 REJECT）。

## M2 重大突破：Cookies 直连 BOSS API（2026-08-12 深夜）
**背景**：浏览器自动化（agent-browser）打开 BOSS 被反爬检测（headless/headed 均白屏，页面被踢 about:blank）。
**方案**：用户导出登录 cookies（含 __zp_stoken__/zp_at 等 15 条）→ 直接调 BOSS 内部搜索接口。
**验证**：`wapi/zpgeek/search/joblist.json?query=教育&city=101210800` → code=0 Success，拿到真实岗位。
**产出**：
- `scripts/fetch-boss-jobs.py`：关键词+城市采集 → 标准化 Job JSON（自动折算时薪/日薪）
- `scripts/scan-boss-jobs.py`：一键"采集→评分→推荐榜"流水线
- cookies 归档 `config/cookies/zhipin_20260812.json`（会过期，过期重导）
- 实测：丽水教育 20 岗 / 项目经理 15 岗，含真实岗位（逸畅通信 boss-06 复现）
